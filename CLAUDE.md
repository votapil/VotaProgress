# VotaProgress - заметки для разработки

Мод для Claude Code: план задачи в панели сбоку и в строке под вводом.

## Команды

```
claude --plugin-dir .          # запустить Claude Code с модом из этой папки
claude plugin test .           # тесты
claude plugin validate .       # проверка мода
npx -y -p typescript tsc -p .claude-plugin/types/tsconfig.json
```

Перед правкой мода загрузи навык `plugin-authoring`: в нём типы и справочник движка.

## Устройство

- `hooks/plan.ts` - модель плана и всё, что из неё считается. Чистые функции.
- `hooks/storage.ts` - записи по сессиям в хранилище мода: ключи `s:<sessionId>`, отметки `drop:<sessionId>:<planId>`, чистка старше 365 дней.
- `hooks/tool.ts` - инструмент `progress` для модели.
- `hooks/rule.ts` - правило в системном промпте и напоминания.
- `hooks/pane.tsx` - панель «этот чат».
- `hooks/register.tsx` - все хуки.
- `types/index.d.ts` - контракт состояния. Без импортов.
- `docs/` (локально, в git не входит) - спецификация и план первого этапа.

## Договорённости

- Процентов нет нигде: ни в панели, ни в ответах модели. Только счёт «3 из 7».
- Тексты мода на русском, дефис вместо тире.
- Сначала падающий тест, потом код.
- Спецификация в `docs/spec.md` отстала от кода: пометки «сейчас» и «крупный», проценты, переименование цели. Перед вторым этапом её надо привести в порядок.

## Второй этап (не начат)

Вид панели «Все проекты»: планы из всех чатов, сгруппированные по папкам, текущий проект раскрыт; поиск; два фильтра-переключателя (статус, период); история; кнопка «ещё 30»; копирование команды `claude --resume <id>`; «выбросить» план через отметки `drop:`. Команда `/progress all` открывает панель сразу на обзоре. Описание в `docs/spec.md`, плана ещё нет.

## Отложено после ревью первого этапа

- субагенты видят инструмент, но не правило: сказать «план ведёт основная сессия» в описании инструмента;
- сбой хранилища виден только в панели, не в строке под вводом;
- отметки `drop:` применяются только при подъёме записи, не при записи (нужно второму этапу);
- два шага с одним `after` встают в обратном порядке;
- `done` на выброшенном шаге возвращает его в план;
- план, где выброшены все шаги, сам не закрывается;
- битый элемент в `plans` отключает инструмент до конца сессии;
- слэш-команда сразу после сжатия съедает напоминание о плане;
- два одновременных вызова инструмента теряют одно изменение;
- вес шага 1-3 больше не влияет на счёт, остался только значок `◆` у веса 3: решить, нужен ли вес.
